# 모바일 세로형 SRPG UI·UX

## 목표

모바일 세로 화면에서 SRPG의 전술성을 유지하면서도 한 손 조작이 편하도록 구성한다.

핵심 원칙은 다음과 같다.

> **전장은 최대한 크게, 정보는 필요할 때만, 조작은 엄지 하나로.**

본 게임은 다음과 같은 전술 요소를 사용하므로 화면에 모든 정보를 동시에 노출하지 않는다.

- 이동 및 이동 확정
- 방향과 시야
- 무기 리치
- 반격
- 지구력
- 베기 / 찌르기
- 오행
- 음양
- 마법
- 적 위험 범위

필요한 순간에 필요한 UI만 나타나는 **Context UI**를 기본으로 한다.

---

# 1. 기본 전투 화면

화면의 약 65~70%를 전장으로 사용한다.

상단에는 턴과 전투 상황을 표시하고,
하단에는 선택한 캐릭터 정보와 행동 UI를 배치한다.

```text
┌──────────────────────┐
│ TURN 4        적 06   │
│ ◉ 위험범위       ☰    │
├──────────────────────┤
│                      │
│          👹          │
│       ▒ ▒ ▒ ▒        │
│          │           │
│      🌳  │  👹       │
│          │           │
│        👤→           │
│       👤 👤          │
│                      │
├──────────────────────┤
│ 주인공 Lv.12          │
│ HP ███████ 86         │
│ ST █████   61         │
│ 火 / 陽 / 검          │
├──────────────────────┤
│ ⚔ 공격   ◇ 기술   ✦ 마법 │
│       ⏸ 대기          │
└──────────────────────┘
```

캐릭터의 핵심 특성은 짧은 아이콘 또는 문자로 표시한다.

예:

- `火` : 오행
- `陽` : 음양
- `검` : 주무기

상세 능력치는 기본 화면에서 숨긴다.

---

# 2. Context UI

모든 행동 버튼을 항상 노출하지 않는다.

현재 상태에 필요한 버튼만 표시한다.

## 평상시

```text
[위험범위]                  [턴 종료]
```

## 유닛 선택 후

```text
[상세]                        [대기]
```

## 이동 확정 후

```text
[공격]   [기술]   [마법]   [대기]
```

이를 통해 전장을 가리는 UI를 최소화한다.

---

# 3. 유닛 선택과 이동

기본 조작은 `Tap → Tap` 구조를 사용한다.

```text
유닛 터치
↓
이동 가능 범위 표시
↓
이동할 칸 터치
↓
이동 예정 위치 Preview
↓
이동 확정
```

한 번의 터치로 즉시 이동을 확정하지 않는다.

첫 번째 입력은 미리보기,
두 번째 입력 또는 확정 버튼은 실제 이동으로 사용한다.

## 이동 Preview

```text
현재 위치 👤
      ↓
예정 위치 ◉
```

하단에는 다음 버튼을 표시한다.

```text
[취소]                 [이동 확정]
```

[[이동과_시야]]의 규칙에 따라 이동을 확정한 이후에는 되돌릴 수 없다.

---

# 4. 공격 대상 선택

공격 대상을 별도의 리스트에서 선택하지 않는다.

공격 가능한 적을 전장에서 직접 선택한다.

```text
[공격]
↓
공격 가능한 적 강조
↓
적 터치
↓
전투 Preview
↓
공격 확정
```

공격 가능한 적을 직접 터치했을 때 공격 Preview로 바로 진입하는 단축 조작도 고려한다.

---

# 5. 전투 Preview

공격 확정 전에 예상 결과를 표시한다.

기본적으로 다음 정보만 우선 표시한다.

- 예상 피해
- 명중률
- 반격 여부
- 지구력 변화

예:

```text
┌─────────────────────┐
│     주인공 → 악귀     │
│                     │
│ 피해 35      피해 18 │
│ 명중 82%    반격 가능 │
│                     │
│ ST 72 → 58          │
│                     │
│ [취소]       [공격]   │
└─────────────────────┘
```

속성 상성이나 상세 계산식 등은 `상세`에서 확인한다.

---

# 6. 베기와 찌르기

[[기술_시스템]]의 공격 타입을 UI에서도 명확하게 구분한다.

## 베기

- 높은 위력
- 상대적으로 낮은 명중률

## 찌르기

- 상대적으로 낮은 위력
- 높은 명중률

기술 선택 시 실제 예상 결과를 함께 표시한다.

```text
베기
DMG 42
HIT 68%

찌르기
DMG 31
HIT 91%
```

플레이어가 별도의 계산 없이 위험과 보상을 비교할 수 있어야 한다.

---

# 7. 지구력 UI

지구력은 [[능력치]]에서 전투의 핵심 자원이므로 HP와 함께 상시 표시한다.

캐릭터 위에는 간략한 두 개의 게이지만 표시한다.

```text
👤
██████  HP
████    ST
```

캐릭터를 선택하면 정확한 수치를 표시한다.

```text
HP 84 / 100
ST 61 / 100
```

지구력 부족으로 공격력이 감소하는 경우 별도의 상태 아이콘을 표시한다.

```text
ST 18 / 100
▼ 공격력 감소
```

---

# 8. 방향과 시야

[[이동과_시야]]의 방향 시스템은 스와이프 중심으로 조작한다.

대기 또는 방향 변경이 가능한 상태에서
캐릭터를 원하는 방향으로 짧게 스와이프한다.

```text
👤
→ Swipe

👤→
```

방향을 선택하는 동안 해당 방향의 시야를 Preview로 표시한다.

```text
      ▒
    ▒ ▒ ▒
  ▒ ▒ ▒ ▒ ▒
      👤→
```

손을 떼면 방향을 확정한다.

## 시야 표시 원칙

모든 캐릭터의 시야를 항상 표시하지 않는다.

### 기본 상태

시야 범위를 숨긴다.

### 유닛 선택

선택한 유닛의 시야만 표시한다.

### 전체 시야 확인

별도의 시야 확인 기능을 통해 아군 전체 시야를 일시적으로 표시한다.

이를 통해 전장 가독성을 유지한다.

---

# 9. 위험 범위

적의 공격 가능 범위 역시 항상 표시하지 않는다.

상단의 `위험범위` 버튼으로 On / Off 한다.

```text
[위험범위]
```

필요할 때만 적의 공격 범위와 위협 지역을 표시하여
이동 범위, 시야, 공격 범위가 동시에 겹치는 것을 방지한다.

---

# 10. 캐릭터 및 적 정보

유닛을 터치했을 때 전체 정보창을 띄우지 않는다.

화면 하단에서 작은 정보 카드가 올라오는 Bottom Sheet 구조를 사용한다.

예:

```text
┌──────────────────────┐
│ 악귀 · Lv.12          │
│ HP 85 / 85            │
│                      │
│ 도끼 / 리치 1          │
│ 火 속성                │
│                      │
│ [상세보기]             │
└──────────────────────┘
```

정보 카드를 위로 스와이프하면 상세 정보를 확인할 수 있다.

상세 정보 예:

- HP
- 지구력
- 근력
- 정신력
- 민첩성
- 이동력
- 시야
- 오행
- 음양
- 무기
- 리치
- 패시브
- 기술
- 연결된 저승 존재

기본 원칙:

> **Tap = 핵심 정보**

> **Swipe Up = 상세 정보**

---

# 11. 마법 UI

[[수호신]] 시스템에서 선신과 악신은 패시브 중심,
선귀와 악귀는 액티브 중심으로 구성한다.

따라서 액티브 마법을 위한 거대한 스킬 목록을 만들지 않는다.

기본 행동 UI:

```text
[공격] [기술] [마법]
```

마법 선택 시 현재 사용할 수 있는 마법만 펼친다.

예:

```text
        [정화]
[공격] [순간이동] [재행동]
```

전투 중 자주 사용하는 마법은 2~3개의 Quick Slot으로 접근할 수 있도록 한다.

---

# 12. 카메라 조작

전장이 한 화면보다 클 경우 다음 조작을 사용한다.

## 한 손가락 Drag

맵 이동.

## Pinch

확대 / 축소.

## 유닛 더블 탭

선택한 유닛을 화면 중앙으로 이동.

## 확대 단계

실질적으로 세 단계 정도를 사용한다.

```text
전체 전술뷰
↓
기본 전투뷰
↓
근접 정보뷰
```

### 전체 전술뷰

전장의 전체적인 배치와 위험 지역 확인.

### 기본 전투뷰

일반적인 이동과 공격에 사용.

### 근접 정보뷰

캐릭터 상태와 전투 정보를 보다 자세히 표시.

---

# 13. 세로형 전장 설계

세로 플레이를 전제로 맵 자체도 세로 방향 진행을 우선한다.

권장 예:

- 8 × 14
- 9 × 16

전투의 기본 진행 방향을 위아래로 형성한다.

```text
      적
      적

   장애물

     아군
     아군
```

가로로 지나치게 긴 전장은 지속적인 카메라 이동을 요구하므로 피한다.

---

# 14. 한 손 조작

핵심 전투 버튼은 화면 하단에 집중한다.

엄지손가락이 자연스럽게 닿는 영역에 다음 기능을 배치한다.

- 공격
- 기술
- 마법
- 대기
- 이동 확정
- 취소

상단에는 전투 중 자주 누르지 않는 기능을 배치한다.

- 턴 정보
- 적 / 아군 숫자
- 위험범위
- 메뉴
- 턴 종료

---

# 15. UI에서 피해야 할 요소

세로 모바일에서는 다음 구성을 지양한다.

- 화면 양옆에 항상 떠 있는 캐릭터 정보창
- 기술 버튼 6~8개 상시 노출
- 이동 / 공격 / 대기를 팝업 리스트로 표시
- 모든 캐릭터의 HP 숫자를 항상 표시
- 이동 범위 + 공격 범위 + 시야 + 위험범위를 동시에 표시
- 작은 아이콘을 지나치게 촘촘하게 배치
- 정확한 작은 칸을 눌러야만 하는 조작
- 상세 능력치를 기본 전투 화면에 상시 노출

---

# 16. 최종 UX 원칙

본 게임은 전술 시스템 자체를 모바일에 맞춰 단순화하기보다
**전술 깊이는 유지하면서 UI를 단계적으로 노출하는 방식**을 사용한다.

```text
평상시
→ 최소 UI

유닛 선택
→ 이동 / 핵심 정보

이동 확정
→ 행동 UI

공격 선택
→ 대상 및 전투 Preview

상세 요청
→ Bottom Sheet
```

이를 통해 복잡한 SRPG 시스템을 유지하면서도
모바일 세로 화면에서 전장 가독성과 한 손 조작성을 확보한다.
