# 기술 설계

| 항목 | 내용 |

## 2D 도트 그래픽

- 사각 타일 기반 전장을 사용한다.
- 캐릭터는 상·하·좌·우 방향을 구분할 수 있는 스프라이트를 사용한다.
- 휘두르기, 뻗기, 사격의 공격 형태가 실루엣만으로 구분되어야 한다.
- 영력과 일반 물리 효과는 색, 외곽선 또는 이펙트 형태로 구분한다.
- 기준 타일 크기와 캐릭터 해상도는 UI 시제품과 기기 성능 테스트 후 확정한다.
- 화면 확대·축소 시 픽셀 보간으로 흐려지지 않도록 정수 배율 또는 최근접 보간을 우선 검토한다.

## 웹과 앱 공통 코드 방향

- 전투 규칙, 캐릭터 데이터, 기술 데이터와 시나리오 데이터는 웹과 앱에서 공유한다.
- 앱은 동일한 게임 코드를 패키징하는 방식을 우선 검토한다.
- 엔진 선정 시 모바일 웹 빌드, 앱 패키징, 20×20 타일맵, 2D 애니메이션, 터치 UI 지원을 필수 조건으로 삼는다.
- 구체적인 엔진은 Godot, Unity 또는 웹 기반 프레임워크를 비교한 뒤 확정한다.

## 데이터 분리

다음 데이터는 코드에서 분리해 수정 가능하게 관리한다.

- 캐릭터 기본 능력치와 성장
- 무기와 기술
- 적과 AI 역할
- 전투 맵과 배치
- 대사와 컷신
- 상점 가격과 제작 재료
- 상태이상과 밸런스 수치

## 자동 저장

자동 저장 시점:

1. 정비 화면에서 출전을 확정했을 때
2. 전투 시작 직전
3. 전투 승리 후 보상을 확정했을 때
4. 능력치·기술 포인트를 배분했을 때
5. 구매·제작·강화·수리를 완료했을 때
6. 컷신 종료와 다음 진행 단계 진입 시

전투 도중에는 각 진영 턴 시작 시 임시 전투 저장을 남기는 방식을 가안으로 한다. 패배 또는 앱 강제 종료 시 최근 진영 턴 시작 상태로 복구한다.

## 저장 안정성

- 저장 중 앱이 종료되어도 이전 정상 저장을 복구할 수 있게 한다.
- 자동 저장 파일은 최소 하나의 이전 버전을 백업한다.
- 게임 버전과 저장 데이터 버전을 함께 기록한다.
- 모바일 웹에서는 브라우저 저장소 삭제 가능성을 안내한다.
- 클라우드 저장과 계정 연동 여부는 추후 확정한다.

## 성능 목표 가안

- 프롤로그 프로토타입 맵: 20×20 타일
- 화면 내 전투 유닛: 프로토타입 기준 12명 이하
- 목표 프레임: 60fps, 저사양 기기에서는 30fps 안정 유지
- 전투 판정은 프레임 속도와 무관하게 동일해야 한다.
